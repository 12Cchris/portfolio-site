# Personal Workshop Log

🔗 사이트 바로가기: https://12cchris.github.io/portfolio-site/

필요해서 만든 개인 프로그램들을 한 페이지에 모아 보여주는 포트폴리오 사이트입니다.
빌드 도구 없이 `index.html` 파일 하나로 동작하는 정적 사이트예요.

## 폴더 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 사이트 전체 (화면, 스타일, 프로젝트 데이터, ADMIN 도구까지 이 파일 하나) |
| `preview.bat` | 내 컴퓨터에서 미리보기 (로컬 서버 실행) |
| `deploy.bat` | GitHub와 동기화하고 올리기 |

## 미리보기

`preview.bat`을 더블클릭하면 로컬 서버가 켜지고 브라우저가 자동으로 열립니다
(Python이면 `http://localhost:8000/index.html`, Node.js면 `http://localhost:3000`).
끄려면 열려 있는 창에서 `Ctrl+C`를 누르세요. Python이나 Node.js 중 하나는 설치되어 있어야 합니다.

`index.html`을 그냥 더블클릭해서(`file://`) 열어도 대부분 그대로 보이지만,
ADMIN 화면의 "GitHub에 저장하고 배포" 기능은 일부 브라우저에서 막힐 수 있습니다.

## 배포 (GitHub Pages)

1. 이 파일을 GitHub 저장소에 `index.html`이라는 이름으로 올립니다.
2. 저장소 **Settings → Pages**에서 Source를 `Deploy from a branch`,
   브랜치는 `main`, 폴더는 `/ (root)`로 설정하고 저장합니다.
3. 잠시 후 `https://<아이디>.github.io/<저장소이름>/` 주소로 접속할 수 있습니다.
4. 이후에는 저장소에 새 커밋만 올리면 자동으로 다시 배포됩니다.
   (올린 뒤 실제 사이트에 보이기까지 보통 30~60초 걸립니다.)

## 코드 수정 후 올리기 (`deploy.bat`)

`index.html`이나 다른 파일을 직접 고쳤다면 `deploy.bat`을 더블클릭하세요.
아래 4단계를 알아서 처리합니다.

1. GitHub의 최신 상태를 확인합니다.
2. 내 컴퓨터에서 바꾼 내용을 커밋합니다. 커밋 메시지는 직접 입력하거나, Enter만 누르면
   날짜로 자동 생성됩니다. (바뀐 게 없으면 건너뜁니다.)
3. ADMIN 화면에서 저장해 GitHub에 올라간 커밋을 내 폴더에 합칩니다.
4. GitHub에 올립니다.

ADMIN 화면에서 저장하면 GitHub에 바로 커밋되고 **내 컴퓨터 폴더에는 반영되지 않기** 때문에,
로컬에서 작업하기 전에 `deploy.bat`으로 한 번 동기화해 두면 안전합니다.

같은 부분을 내 컴퓨터와 ADMIN 화면에서 둘 다 고쳐서 충돌이 나면, 화면에서 고를 수 있습니다.
`1`은 GitHub 버전을 남기고 내 로컬 수정을 버리는 것, `2`는 멈추고 직접 해결하는 것입니다.
(Git이 설치되어 있고, 이 폴더가 `origin/main`에 연결된 저장소여야 합니다.
줄바꿈 차이로 가짜 변경이 뜨지 않도록 `deploy.bat`이 `core.autocrlf true`를 설정합니다.)

## 프로젝트 추가하는 법

두 가지 방법이 있습니다.

**방법 A. 사이트의 ADMIN 화면 사용 (코드 수정 없이)**
사이트 상단의 **ADMIN** 메뉴에서 비밀번호를 입력해 들어갑니다.

1. **GitHub 연결 정보**: 아이디, 저장소 이름, 브랜치(`main`), 파일 경로(`index.html`),
   Personal Access Token을 입력합니다. 입력하면 자동으로 저장됩니다.
2. **프로젝트 편집**: 프로젝트가 한 줄씩(번호 / 제목 / 상태 / 버전 / 플랫폼 / 업데이트) 보입니다.
   설명, 링크(최대 2개), 아이콘, 기술 스택, 특징은 **상세** 버튼으로 펼쳐서 고칩니다.
   순서 이동(▲▼), 삭제, **+ 새 프로젝트 추가**, 모두 펼치기/접기, 일괄 정렬을 쓸 수 있습니다.
3. **GitHub에 저장하고 배포** 버튼을 누르면 바로 GitHub에 커밋되고, 잠시 뒤 실제 사이트에 반영됩니다.
   커밋 메시지는 비워두면 기본 문구로 들어갑니다.

**방법 B. 코드 직접 수정**
`index.html`을 열어 `PROJECTS_DATA_START` ~ `PROJECTS_DATA_END` 마커 사이의
`PROJECTS` 배열에 객체를 하나 추가하면 카드가 자동으로 생깁니다. 각 필드 설명은
그 위 주석에 적혀 있습니다. (`link2`, `link2Label`로 두 번째 링크도 달 수 있고,
`updatedAt`은 `"2026-09"`처럼 연월만 적어도 됩니다.)

- ADMIN 화면으로 저장하든, 코드를 직접 고쳐서 커밋하든 결과는 동일합니다
  (같은 `PROJECTS_DATA_START` ~ `PROJECTS_DATA_END` 영역을 사용합니다).
- 두 방법을 섞어 써도 되지만, ADMIN 화면은 항상 GitHub에 있는 최신 파일을
  기준으로 편집하는 것이 아니라 **화면을 열 때 로드된 내용을 기준으로 편집**하므로,
  코드를 직접 고친 직후에는 ADMIN 화면을 새로고침한 뒤 사용하는 걸 권장합니다.

## 검색·필터·정렬

카탈로그 위에서 이름, 설명, 기술 스택으로 검색하고, 상태별 필터 버튼으로 좁힐 수 있습니다.
정렬 드롭다운은 기본 순서 / 최근 업데이트순 / 오래된 업데이트순 / 이름순(가나다) / 상태순입니다.
`updatedAt`이 없는 프로젝트는 어떤 정렬에서도 맨 뒤로 갑니다.

이 정렬은 **화면에 보이는 순서만** 바꿉니다. 실제 데이터 순서(기본 순서)를 바꾸려면
ADMIN 화면의 **일괄 정렬**에서 기준을 고르고 **이 순서로 정렬 적용**을 누른 뒤 저장하세요.

## 아이콘 추가하는 법

`icon` 필드에 내장 아이콘 이름(`clock`, `music`, `wallet`, `code`, `star`, `folder`,
`chart`, `lock`, `phone`, `bell`, `globe`) 외의 이름을 적으면,
[lucide.dev/icons](https://lucide.dev/icons)에서 같은 이름의 아이콘을 자동으로 가져와
표시합니다. 예: `icon: "rocket"`
인터넷이 없거나 이름을 찾지 못하면 기본 아이콘이 그대로 남습니다.
외부에서 받아온 아이콘은 스크립트와 이벤트 속성을 제거한 뒤에만 화면에 넣습니다.

## 상태(status) 값 추가/변경

`STATUS_CONFIG` 객체에서 상태 key·라벨·색상·순서를 관리합니다. 새 상태가 필요하면
이 객체에 한 줄만 추가하면 됩니다. (`index.html` 안 주석 참고)
ADMIN 화면에서는 상태 종류 자체를 편집할 수 없고, 프로젝트별 상태 드롭다운과
상태순 정렬이 이 값을 따릅니다.

## 제작자 정보 링크 추가/변경

CREATOR INFO 화면의 버튼(GitHub, 이메일 등)은 `CREATOR_LINKS` 배열에서 관리합니다.
한 줄만 추가하면 버튼이 생깁니다. 이메일은 링크가 아니라 **클릭하면 주소가 복사되는 버튼**이고,
스팸 수집 봇을 피하려고 주소를 거꾸로 뒤집어 저장해 둡니다. 자세한 형식은 `index.html` 안 주석에 있습니다.

## 관리자(ADMIN) 도구에 대한 주의사항

- ADMIN 화면은 상단 메뉴의 **ADMIN** 버튼으로 들어갑니다. 주소 끝에 `#admin`을 붙여도 바로 열립니다.
  예) `https://12cchris.github.io/portfolio-site/#admin`
- 비밀번호는 이 파일 안에 SHA-256 해시 형태로 고정되어 있습니다 (평문은 파일 어디에도
  없습니다). 비밀번호를 바꾸려면 새 비밀번호의 SHA-256 해시를 구해서 `index.html`의
  `ADMIN_PASS_HASH` 상수 값만 바꾸면 됩니다.
- 비밀번호를 5번 연속 틀리면 5분 동안 잠깁니다. 페이지를 새로고침하면 항상 다시 잠기고,
  자리를 비울 때는 **🔒 잠그기** 버튼으로 바로 잠글 수 있습니다.
- 이 방식도 정적 사이트의 한계상 완전한 보안은 아니라 **가벼운 잠금장치**입니다.
  실제 방어선은 여전히 GitHub 토큰이며, 비밀번호는 화면을 우연히 여는 것을 막는
  용도입니다.
- GitHub Personal Access Token은 이 브라우저의 로컬 저장소에 **관리자 비밀번호로 암호화되어**
  저장되고, 잠금을 풀 때 복호화되어 채워집니다. 토큰은 GitHub API로만 직접 전송됩니다.
  비밀번호를 바꾸면 이전에 저장한 토큰은 열 수 없으니 토큰을 다시 입력해 주세요.
  다른 사람의 기기나 공용 컴퓨터에는 입력하지 마시고, 필요하면 **저장된 정보 지우기**로 지우세요.
- 토큰은 이 저장소에 대해 **Contents: Read and write** 권한만 준
  Fine-grained personal access token으로 새로 발급해서 쓰는 걸 추천합니다.
- 저장소를 Private으로 바꿔도 배포된 사이트 자체는 누구나 볼 수 있는 공개 페이지입니다
  (정적 사이트라 페이지 소스가 그대로 노출됩니다). Private 저장소에서 GitHub Pages를
  쓰려면 GitHub Pro 이상 유료 플랜이 필요합니다.
