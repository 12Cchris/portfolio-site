# Personal Workshop Log

🔗 사이트 바로가기: https://12cchris.github.io/portfolio-site/

필요해서 만든 개인 프로그램들을 한 페이지에 모아 보여주는 포트폴리오 사이트입니다.
빌드 도구 없이 `index.html` 파일 하나로 동작하는 정적 사이트예요.

## 폴더 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 사이트 전체 (화면, 스타일, 프로젝트 데이터, ADMIN 도구까지 이 파일 하나) |
| `admin-verifier.js` | 관리자 비밀번호 검증값 (index.html과 분리되어 있어, index.html을 덮어써도 비밀번호 설정이 유지됨) |
| `preview.bat` | 내 컴퓨터에서 미리보기 (로컬 서버 실행) |
| `deploy.bat` | GitHub와 동기화하고 올리기 |
| `make-password-hash.html` | 관리자 비밀번호 검증값 생성 도구 (내 컴퓨터에서만 사용) |

## 미리보기

`preview.bat`을 더블클릭하면 로컬 서버가 켜지고 브라우저가 자동으로 열립니다
(Python이면 `http://localhost:8000/index.html`, Node.js면 `http://localhost:3000`).
끄려면 열려 있는 창에서 `Ctrl+C`를 누르세요. Python이나 Node.js 중 하나는 설치되어 있어야 합니다.

`index.html`을 그냥 더블클릭해서(`file://`) 열어도 대부분 그대로 보이지만,
ADMIN 화면의 "GitHub에 저장하고 배포" 기능은 일부 브라우저에서 막힐 수 있습니다.

## 배포 (GitHub Pages)

1. 이 파일을 GitHub 저장소에 `index.html`이라는 이름으로 올립니다.
2. 저장소 **Settings → Pages**에서 Source를 `Deploy from a branch`,
   브랜치는 `main`, 폴더는 `/ (root)`로 설정하고 저장합니다.
3. 잠시 후 `https://<아이디>.github.io/<저장소이름>/` 주소로 접속할 수 있습니다.
4. 이후에는 저장소에 새 커밋만 올리면 자동으로 다시 배포됩니다.
   (올린 뒤 실제 사이트에 보이기까지 보통 30~60초 걸립니다.)

## 코드 수정 후 올리기 (`deploy.bat`)

`index.html`이나 다른 파일을 직접 고쳤다면 `deploy.bat`을 더블클릭하세요.
아래 4단계를 알아서 처리합니다.

1. GitHub의 최신 상태를 확인합니다.
2. 내 컴퓨터에서 바꾼 내용을 커밋합니다. 커밋 메시지는 직접 입력하거나, Enter만 누르면
   날짜로 자동 생성됩니다. (바뀐 게 없으면 건너뜁니다.)
3. ADMIN 화면에서 저장해 GitHub에 올라간 커밋을 내 폴더에 합칩니다.
4. GitHub에 올립니다.

ADMIN 화면에서 저장하면 GitHub에 바로 커밋되고 **내 컴퓨터 폴더에는 반영되지 않기** 때문에,
로컬에서 작업하기 전에 `deploy.bat`으로 한 번 동기화해 두면 안전합니다.

같은 부분을 내 컴퓨터와 ADMIN 화면에서 둘 다 고쳐서 충돌이 나면, 화면에서 고를 수 있습니다.
`1`은 GitHub 버전을 남기고 내 로컬 수정을 버리는 것, `2`는 멈추고 직접 해결하는 것입니다.
(Git이 설치되어 있고, 이 폴더가 `origin/main`에 연결된 저장소여야 합니다.
줄바꿈 차이로 가짜 변경이 뜨지 않도록 `deploy.bat`이 `core.autocrlf true`를 설정합니다.)

## 프로젝트 추가하는 법

두 가지 방법이 있습니다.

**방법 A. 사이트의 ADMIN 화면 사용 (코드 수정 없이)**
사이트 상단의 **ADMIN** 메뉴에서 비밀번호를 입력해 들어갑니다.

1. **GitHub 연결 정보**: 아이디, 저장소 이름, 브랜치(`main`), 파일 경로(`index.html`),
   Personal Access Token을 입력합니다. 입력하면 자동으로 저장됩니다.
2. **프로젝트 편집**: 프로젝트가 한 줄씩(번호 / 제목 / 상태 / 버전 / 플랫폼 / 업데이트) 보입니다.
   설명, 링크(최대 2개), 아이콘, 기술 스택, 특징은 **상세** 버튼으로 펼쳐서 고칩니다.
   순서 이동(▲▼), 삭제, **+ 새 프로젝트 추가**, 모두 펼치기/접기, 일괄 정렬을 쓸 수 있습니다.
3. **GitHub에 저장하고 배포** 버튼을 누르면 바로 GitHub에 커밋되고, 잠시 뒤 실제 사이트에 반영됩니다.
   커밋 메시지는 비워두면 기본 문구로 들어갑니다.

**방법 B. 코드 직접 수정**
`index.html`을 열어 `PROJECTS_DATA_START` ~ `PROJECTS_DATA_END` 마커 사이의
`PROJECTS` 배열에 객체를 하나 추가하면 카드가 자동으로 생깁니다. 각 필드 설명은
그 위 주석에 적혀 있습니다. (`link2`, `link2Label`로 두 번째 링크도 달 수 있고,
`updatedAt`은 `"2026-09"`처럼 연월만 적어도 됩니다.)

- ADMIN 화면으로 저장하든, 코드를 직접 고쳐서 커밋하든 결과는 동일합니다
  (같은 `PROJECTS_DATA_START` ~ `PROJECTS_DATA_END` 영역을 사용합니다).
- 두 방법을 섞어 써도 됩니다. ADMIN 화면은 **저장 직전에 GitHub의 현재 프로젝트 목록과 비교**해서,
  이 화면을 연 뒤 다른 곳에서 저장된 변경(잠금 포함)이 있으면 덮어쓰지 않고 멈춘 다음
  "최신 목록 불러오기"를 물어봅니다. 배포된 사이트에서 ADMIN을 처음 열 때도 GitHub 쪽이 더 최신이면
  자동으로 그 내용을 기준으로 불러옵니다. (내 컴퓨터/localhost에서 연 경우는 직접 고친 코드를 존중해서
  저장할 때만 비교합니다.)
- **새 `index.html`로 덮어쓰기 전에** ADMIN에서 저장한 내용이 있다면 먼저 `deploy.bat`을 실행해 GitHub 내용을
  내 폴더로 가져오세요. 안 그러면 새 파일 안의 예전 프로젝트 목록이 GitHub의 목록(잠금 포함)을 되돌릴 수 있습니다.

## New Project / New Update 표시 (7일간)

관리자 화면에서 저장하면, 저장한 날부터 **7일간** 카드에 표시가 붙습니다.

- **새 프로젝트를 추가**해서 저장 → 빨간 **New Project**
- 기존 프로젝트의 **버전(model)을 바꿔서 저장** → 파란 **New Update**
- 기준일은 `newAt`("YYYY-MM-DD"), 종류는 `newKind`("project" 또는 "update")에 자동으로 기록됩니다. 직접 쓰지 않아도 됩니다.
  (`newKind`가 없는 예전 데이터는 New Update로 표시됩니다.)
- 아직 New Project 기간(7일) 중인 프로젝트는 버전을 고쳐도 New Project가 그대로 유지됩니다.
- 버전을 바꾸지 않고 다른 내용만 고치면 표시는 붙지 않습니다.
- 7일이 지나면 저절로 사라지고(`newAt` 값은 남아 있어도 표시되지 않음), 저장이 실패하면 기준일은 기록되지 않습니다.
- 잠근 프로젝트의 `newAt`/`newKind`는 암호화된 내용 안에 들어가서, **잠금을 해제해야** 표시가 보입니다.
- 기간을 바꾸려면 `index.html`의 `NEW_DAYS` 값을 고치세요.

## 관리자 로그인이 안 될 때

로그인 화면에 어떤 **검증 방식**이 적용 중인지 표시됩니다.

- "예전 방식(SHA-256)"이 보이는데 새 비밀번호를 만들었다면, `admin-verifier.js`가 `index.html`과 같은 폴더에 없거나
  아직 GitHub에 올라가지 않은 것입니다. 로컬 파일을 고쳤다면 `deploy.bat`으로 올려야 배포된 사이트에서도 바뀝니다.
- 5번 틀리면 5분간 잠기며, 잠긴 동안에는 화면을 열 때 남은 시간이 표시됩니다. 급하면 브라우저 개발자도구
  (F12) → Application → Local Storage에서 `admin-login-attempts` 항목을 지우면 풀립니다.
- "오류가 났습니다"가 나오면 `admin-verifier.js`의 `ADMIN_PASS_VERIFIER`가 잘못 붙여넣어진 것입니다. `make-password-hash.html`로 다시 만들어 붙이세요.
- 같은 비밀번호로 `http://` 주소(localhost 제외)에서 열면 확인 기능을 쓸 수 없습니다. https나 `preview.bat`(localhost)로 여세요.

## 프로젝트 잠그기 (정보 숨기기)

특정 프로젝트의 정보를 방문자에게 보이지 않게 잠글 수 있습니다.

1. ADMIN 화면에서 프로젝트의 **상세**를 펼치고 **🔒 이 프로젝트 잠그기**를 체크합니다.
   (제목까지 숨기고 싶으면 **제목도 숨기기**를 함께 체크하세요. 공개 화면에는 "비공개 프로젝트"로 나옵니다.)
2. **GitHub에 저장하고 배포**를 누르면, 그 프로젝트의 설명·링크·태그·특징·버전·플랫폼·아이콘·상태가
   **관리자 비밀번호로 암호화**되어 저장됩니다. 소스(`PROJECTS` 영역)에는 암호문만 남습니다.
3. 방문자에게는 상태가 **비공개**인 잠금 카드만 보입니다. 카드의 **🔒 잠금 해제**에서
   관리자 비밀번호를 입력하면 그 화면에서만 내용이 열리고(새로고침하면 다시 잠김),
   **🔒 다시 잠그기**로 바로 닫을 수도 있습니다.
4. 잠금을 풀려면 같은 체크박스를 끄고 다시 저장하면 됩니다.
5. 상태 드롭다운의 **비공개**는 카드에 붙는 이름표일 뿐, 그것만으로는 설명·링크 같은 정보가 숨겨지지 않습니다.
   정보를 숨기려면 반드시 **잠그기**를 쓰세요. (상태를 비공개로 바꾸면 잠글지 물어봅니다.)

주의할 점:

- 잠금 암호는 **관리자 비밀번호와 같은 비밀번호**입니다. 암호문이 공개 소스에 들어가므로
  비밀번호가 짧거나 쉬우면 뚫릴 수 있습니다. 충분히 길고 어려운 비밀번호를 쓰세요.
- 관리자 비밀번호(`ADMIN_PASS_HASH`)를 바꾸면, 이전 비밀번호로 잠근 항목은 ADMIN 화면에서
  열 수 없습니다(저장해도 기존 잠금은 그대로 유지됩니다). 비밀번호를 바꾸기 전에 잠금을 모두 풀고
  저장한 뒤, 바꾼 다음 다시 잠그세요.
- **저장했는데 잠금이 안 보일 때**: 저장 결과 메시지를 먼저 확인하세요. "GitHub 파일에서 변경 내용을 다시 확인했습니다"가
  나왔다면 커밋은 정상입니다. 그 뒤에는 아래 둘 중 하나입니다.
  - `preview.bat`으로 연 화면(localhost)이나 내 컴퓨터의 `index.html`은 GitHub에 저장해도 **내 폴더의 파일은 바뀌지 않아서**
    새로고침하면 예전 내용으로 돌아옵니다. `deploy.bat`을 실행해 GitHub 내용을 폴더로 가져오거나, 배포된 사이트 주소에서 확인하세요.
  - 배포된 사이트는 커밋 뒤 30~60초 걸리고, 브라우저 캐시 때문에 안 바뀌어 보이면 Ctrl+F5로 새로고침하세요.
  - GitHub에 올라간 `index.html`이 잠금 기능이 없는 예전 버전이면 저장이 중단됩니다. 새 `index.html` 전체를 먼저 올리세요.
  - 잠근 뒤 **예전 `index.html`을 덮어써서 올리거나, 예전 화면에서 ADMIN 저장**을 하면 잠금이 사라질 수 있습니다.
    ADMIN은 이제 저장 전에 GitHub의 최신 목록과 비교해 막아 주지만, 파일을 직접 덮어쓸 때는 먼저 `deploy.bat`으로 동기화하세요.
- **이미 공개된 적 있는 정보**는 GitHub 커밋 기록과 검색·캐시에 남아 있을 수 있습니다.
  잠근다고 과거 기록까지 지워지지는 않습니다.

## 검색·필터·정렬

카탈로그 위에서 이름, 설명, 기술 스택으로 검색하고, 상태별 필터 버튼으로 좁힐 수 있습니다.
정렬 드롭다운은 기본 순서 / 최근 업데이트순 / 오래된 업데이트순 / 이름순(가나다) / 상태순입니다.
`updatedAt`이 없는 프로젝트는 어떤 정렬에서도 맨 뒤로 갑니다.

이 정렬은 **화면에 보이는 순서만** 바꿉니다. 실제 데이터 순서(기본 순서)를 바꾸려면
ADMIN 화면의 **일괄 정렬**에서 기준을 고르고 **이 순서로 정렬 적용**을 누른 뒤 저장하세요.

## 아이콘 추가하는 법

`icon` 필드에 내장 아이콘 이름(`clock`, `music`, `wallet`, `code`, `star`, `folder`,
`chart`, `lock`, `phone`, `bell`, `globe`) 외의 이름을 적으면,
[lucide.dev/icons](https://lucide.dev/icons)에서 같은 이름의 아이콘을 자동으로 가져와
표시합니다. 예: `icon: "rocket"`
인터넷이 없거나 이름을 찾지 못하면 기본 아이콘이 그대로 남습니다.
외부에서 받아온 아이콘은 스크립트와 이벤트 속성을 제거한 뒤에만 화면에 넣습니다.

## 상태(status) 값 추가/변경

`STATUS_CONFIG` 객체에서 상태 key·라벨·색상·순서를 관리합니다. 새 상태가 필요하면
이 객체에 한 줄만 추가하면 됩니다. (`index.html` 안 주석 참고)
ADMIN 화면에서는 상태 종류 자체를 편집할 수 없고, 프로젝트별 상태 드롭다운과
상태순 정렬이 이 값을 따릅니다.

## 제작자 정보 링크 추가/변경

CREATOR INFO 화면의 버튼(GitHub, 이메일 등)은 `CREATOR_LINKS` 배열에서 관리합니다.
한 줄만 추가하면 버튼이 생깁니다. 이메일은 링크가 아니라 **클릭하면 주소가 복사되는 버튼**이고,
스팸 수집 봇을 피하려고 주소를 거꾸로 뒤집어 저장해 둡니다. 자세한 형식은 `index.html` 안 주석에 있습니다.

## 관리자(ADMIN) 도구에 대한 주의사항

- ADMIN 화면은 상단 메뉴의 **ADMIN** 버튼으로 들어갑니다. 주소 끝에 `#admin`을 붙여도 바로 열립니다.
  예) `https://12cchris.github.io/portfolio-site/#admin`
- 비밀번호 원문은 파일 어디에도 없고, **검증값(해시)** 만 들어 있습니다. 다만 소스가 공개되어 있어
  검증값도 누구나 볼 수 있으므로, 비밀번호가 짧거나 흔하면 검증값에서 역으로 찾아낼 수 있습니다.
  그래서 **`make-password-hash.html`** 로 새 비밀번호의 검증값(솔트 + PBKDF2 60만 회)을 만들어
  **`admin-verifier.js`** 의 `ADMIN_PASS_VERIFIER` 줄에 넣어 쓰는 것을 권장합니다.
  검증값이 별도 파일이라 `index.html`을 새로 받아 덮어써도 비밀번호 설정이 그대로 유지됩니다.
  이 파일이 없거나 값이 `null`이면 예전 `ADMIN_PASS_HASH`(단순 SHA-256)가 쓰입니다.
  - `make-password-hash.html`은 내 컴퓨터에서 열어서만 쓰고, GitHub에 올리지 않아도 됩니다.
  - 비밀번호는 12자 이상, 다른 곳에서 쓰지 않는 것으로 정하세요.
  - 비밀번호를 바꾸면 이전 비밀번호로 잠근 프로젝트와 저장해 둔 토큰은 열 수 없습니다.
    잠금은 먼저 풀고 저장한 뒤 바꾸고, 토큰은 다시 입력하세요.
- 비밀번호를 5번 연속 틀리면 5분 동안 잠깁니다. 페이지를 새로고침하면 항상 다시 잠기고,
  자리를 비울 때는 **🔒 잠그기** 버튼으로 바로 잠글 수 있습니다.
- 이 방식도 정적 사이트의 한계상 완전한 보안은 아니라 **가벼운 잠금장치**입니다.
  실제 방어선은 여전히 GitHub 토큰이며, 비밀번호는 화면을 우연히 여는 것을 막는
  용도입니다.
- GitHub Personal Access Token은 이 브라우저의 로컬 저장소에 **관리자 비밀번호로 암호화되어**
  저장되고, 잠금을 풀 때 복호화되어 채워집니다. 토큰은 GitHub API로만 직접 전송됩니다.
  비밀번호를 바꾸면 이전에 저장한 토큰은 열 수 없으니 토큰을 다시 입력해 주세요.
